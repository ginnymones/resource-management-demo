# Resource Management Ecosystem — Demo

A matchmaker and capacity-planning platform for cross-utilization: find people with the right skills **and** the available hours, request them for a project, and route the approval.

> **This repository is a demo.** All people, teams, processes, hours and requests are fictional and generated by `prisma/seed-demo.ts`. It contains no real employee or company data.

## Stack
Next.js (App Router) · TypeScript · Tailwind + shadcn/ui · Prisma 7 · PostgreSQL

## Run locally

```bash
npm install

# Any empty Postgres database works, e.g. a throwaway container:
docker run -d --name resource-demo-db -e POSTGRES_PASSWORD=demo -e POSTGRES_DB=demo -p 5433:5432 postgres:16

# .env
# DIRECT_URL="postgresql://postgres:demo@localhost:5433/demo"
# DATABASE_URL="postgresql://postgres:demo@localhost:5433/demo"

npx prisma migrate deploy   # or: npx prisma db push
npx tsx prisma/seed-demo.ts
npm run dev
```

Open http://localhost:3000 and sign in with PIN `123456`:

### Using Supabase instead of local Postgres
Create a **new, separate** Supabase project for the demo and put its connection strings in `.env` (`DIRECT_URL`, `DATABASE_URL`). Then run `npx prisma db push` and `CONFIRM_WIPE=<your-db-host> npx tsx prisma/seed-demo.ts`. The seed deletes all rows, so it refuses to run against a non-local host unless you pass `CONFIRM_WIPE` with that exact host. Never point it at a database with real data.

Re-running the seed resets the database to the same fictional dataset (dates are relative to today).

Documentation lives in [`docs/wiki`](docs/wiki/README.md).
